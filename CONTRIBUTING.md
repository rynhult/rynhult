# Contributing

Discuss significant changes with the maintainer before implementation. Keep contributions
focused and include regression tests for bugs. Use artificial accounts, example.com /
example.lan and documentation IP addresses in fixtures and documentation.

The first planned public release is `v0.15.0-rc.1`, after the feature freeze and
separate owner publication approval. The intended public repository is
`rynhult/rynhult`; use the reviewed source supplied by the maintainer until then.
Never open a public issue containing private deployment details.

V1 targets small teams. Enterprise identity and delegated roles/teams are parked after v1,
ready for work on request or from contributions.
Cloudflare is qualified; the other DNS adapters remain offered in preview pending qualification.

See [development and verification](docs/wiki/Internal/Development.md) for development and verification commands.
Contributions are provided under the MIT License, with existing third-party notices
retained. Report vulnerabilities through `SECURITY.md`, rather than public issues.

Be respectful, discuss the work rather than the person, and avoid harassment or sharing
another person's private information. The maintainer may close or remove abusive content.
