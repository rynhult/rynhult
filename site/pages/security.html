Report a vulnerability

Please report suspected vulnerabilities in Rynhult privately, not in a public issue.

Email security@rynhult.dev.

What to include

  • The affected version or commit.
  • The impact, and what an attacker needs first.
  • A minimal reproduction using artificial accounts and documentation addresses, such as example.com and 192.0.2.10.

Leave out credentials, tokens, personal data, private network details and session transcripts.

What happens next

The maintainer coordinates a fix and its disclosure with you. No response time or supported-version guarantee has been set yet.

Verify a source release

Download the public release key and inspect it with gpg --show-keys --with-subkey-fingerprint rynhult-release-key.asc. Compare both full fingerprints with an independently trusted copy before importing:

Primary fingerprint (certification only)
0C2C E126 57BD 833F B5B5 63B2 B555 F6E1 2799 0DB5
Signing subkey fingerprint
B072 4912 051F F1F2 74CD EE7F EDE4 F41B 077B D2A7

Stop if either differs. For a published source release, download its archive, BUILD, SHA256SUMS and SHA256SUMS.asc into one folder. After importing the checked key with gpg --import rynhult-release-key.asc, run gpg --verify SHA256SUMS.asc SHA256SUMS, then sha256sum -c SHA256SUMS. On macOS use shasum -a 256 -c SHA256SUMS for the checksum step.

Do not install if the signature is missing or either check fails. Only SHA256SUMS is signed. Its hashes cover the listed files, not Git clones or release tags. A signature does not prove freshness or software safety. The in-app updater does not verify signatures yet. Release signing and upload are owner-run steps; publishing this key does not mean a release is already available or signed.
