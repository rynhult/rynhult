# AC-054 shell accessibility pass — November 2026

Reviewed 2026-11-01 on `a11y-shell`, based on `shell-p1c`
(`4065612cfa5d40ff6e3d5496dd6d79d5dbfee91b`). The new-shell feature and the
person's opt-in were both enabled in an isolated e2e installation. Providers,
accounts, projects and terminal processes were test fixtures. No live instance
or real session was accessed.

## Findings and contained fixes

No High findings in the audited paths. Two Medium and three Low findings:

| ID | Severity | Reproduction / cause | Resolution |
|---|---|---|---|
| AS-1 | Medium | Focus Tools in the desktop rail, narrow to 390px: CSS hides the focused control and Chromium blurs it to body before the media effect. Widening an open Browse drawer also needed an explicit desktop target. | `shell/Shell.tsx`: retain the last shell focus target; move hidden navigation focus to the matching bottom control or More. On widening, close Browse and focus its corresponding desktop rail control. Active content focus is left alone. |
| AS-2 | Medium | A long project name makes New session wider than the phone header. The outer shell clips it, so document scrollWidth alone falsely passes. The phone brand could also shrink to 34px and overlap the hostname. | `shell/Shell.css`, `Shell.tsx`, `ContinueWorking.tsx`: bound and wrap launch labels, preserving the entire accessible name; keep the brand's content width. Both header and Continue launch controls are checked against viewport bounds. |
| AS-3 | Low | Rail arrow/Home/End handlers intercepted modified shortcuts and IME key events. | `shell/Shell.tsx`: leave prevented, composing/229 and modified events alone; ordinary arrows still move focus without navigating. |
| AS-4 | Low | Project paging had its own live span, while short/empty search results had no shared result announcement. | `shell/Sidebar.tsx`: use the app's shared announcer for changed counts/empty results, debounce editing and suppress unchanged notices. Remove the independent live span. |
| AS-5 | Low | Coarse-pointer sidebar links were 36px high; the brand link was 22.5px high. These missed the intended 44px touch affordance (not a claim that every 36px link violates WCAG AA). | `shell/Shell.css`: minimum 44px coarse-pointer shell links/brand/launch actions. Bottom rail and shared icon/popover controls keep their existing touch sizing. |

These changes preserve routes, permissions, feature/personal opt-in, the per-load
shell latch, native terminal ownership and the approved layout. No new navigation
mode, preference, global keyboard handler or visual design system was introduced.
The Guide's New layout keyboard section describes the changed behavior.

Keyboard tests use real keyboard events after locating/focusing the target under
test. They are deterministic browser regressions, not a claim that a person
completed every journey using assistive hardware. Reflow uses equivalent layout
viewports rather than automating Chrome's browser-toolbar zoom. Screen-reader
speech, OS scaling and real phone keyboards remain manual qualification.

## Decisions / follow-up proposals

No design decision blocks the contained fixes. Keep the approved landmarks,
buttons, layout preference/latch and explicit navigation behavior.

- **Manual qualification:** NVDA/Firefox and VoiceOver/Safari should verify the
  spoken order of rail modes, changed counts, header reorder and dialog returns;
  check F6/media-key behavior and 200%/400% browser zoom on actual devices. Axe and
  DOM/live-region checks do not establish speech timing or reading usability.
- **Long-name presentation:** wrapping preserves information and targets. If the
  owner prefers a shorter phone launch label, that needs a separate copy/design
  decision with an accessible full target name; do not silently truncate it here.
- **Larger navigation scale:** Projects is bounded/paged, while Sessions/Tools
  retain their approved layouts. Any further grouping/virtualization or shortcut
  changes need design and focused assistive-technology proof, not this patch.

GO for the contained shell accessibility fixes once the coordinator's combined
checks pass. This is not a whole-product WCAG conformance certificate; physical
assistive-technology and unexercised states remain explicitly unqualified. Exact
commands and final focused results are in the accompanying handoff.
