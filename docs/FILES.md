# Files and editor

Approved scope: the owner's Files and editor plan item, 2026-10-22.

Every project, local workspace and session worktree gets a Files tab. The browser loads one directory at a time and opens bounded text in a bundled CodeMirror editor, with a live Markdown preview. Phones can collapse the tree. Images get a preview; other binary files get a bounded download. Protected names remain listed with a lock.

accd authorizes the project or session with the existing ownership checks and forwards the database's folder, host and agent account to new broker operations. It never opens project files itself. The existing broker link handles remote hosts. Brokers validate relative paths and walk directory descriptors without following symlinks, including internal symlinks, and refuse special files. This walk starts at the configured allowed root and includes every component leading to the registered workspace root; a descriptor remains open throughout the operation, including git subprocesses and rename destinations. Protected-name checks include the registered root and its ancestors, so roots inside git internals or credential folders are refused. Secret protection matches the guard's protected names and credential folders, additionally blocking the run folder and git internals. Reads are bounded; all text returned to the browser passes through vault redaction, including conflict versions. Redacted text cannot be saved back over the original. Binary delivery must also pass secret redaction checks.

Writes use a content revision from the opened file, a per-directory advisory lock and same-directory temporary files plus atomic replacement. A changed revision returns the current text without overwriting it; the editor shows the draft and current version. This protects cooperating editor requests; agents do not take the lock, so external changes in the final check/replace interval remain a filesystem limitation. Creating is exclusive, renaming refuses overwrite, directories delete only when empty; directory renames validate descendants and preserve ordinary contents. Destructive UI actions require confirmation.

Optional Save and commit uses the signed-in person's stored name and email, commits only the selected paths on the current local branch, disables hooks, and never invokes push. Audits contain paths and outcomes, never contents or commit messages. A running session in the folder produces a warning rather than a lock.

Tests cover descriptor confinement, secret policy, bounds, binary detection, optimistic conflicts, local commit identity and isolation, scoped authorization and remote routing, redaction, and the browser's Markdown/save/commit/conflict path. The Guide documents limits and recovery; the plan and changelog record delivery.
