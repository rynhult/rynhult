# Rynhult 0.15.0-rc.4 (release candidate)

These notes cover PRs #419–#425. Tagging, signing, publication, deployment and
release qualification are separate owner steps.

Rynhult supervises coding-agent CLIs on your machines from a browser. This
candidate keeps the self-hosted Linux main and existing browser and node scope.
Ubuntu 24.04+ and Debian 13+ with systemd remain the qualified main targets.

## New for you

- **Changes** offers **Commit all** and **Push**, with a review of what will be
  committed or sent. Commit all requires a session at the repository root.
- Permission requests in **Inbox** have **Approve / Deny** controls. The phone
  setup hint now appears in your personal Inbox information.
- **Host → Backups** can use a folder or USB disk on the server, alongside the
  existing machine and S3 targets.
- Owners can manage the dashboard's GitHub token in **Providers**. Clean git
  installations exactly at a release tag can use the signed release updater;
  see [Updating](../wiki/User-Guide/Updating.md#troubleshooting) for requirements.
- Project navigation uses two tab rows in the new layout. Settings and sidebar
  navigation are less crowded, and Grid puts desktop terminal controls in the
  tile header to leave more room for output.
- **Archive all stopped** clears eligible stopped sessions from the active list.
  Idle Claude shells have clearer status.

## Safety and security

- Offline sign-in recovery codes give you a way back if you lose your
  authenticator. A root administrator also has an offline owner MFA reset route;
  follow [People and sign-in](../wiki/User-Guide/People-and-Sign-in.md#if-you-lose-your-authenticator).
- New Claude sessions default to **Your Claude login (subscription)**. To use
  API billing, grant the appropriate Anthropic credential and select
  **API key: <key name> (API billing)** in New session. The stored choice survives
  restart and resume; subscription sessions retain the automation guard. Teams,
  schedules and other automation needing API billing must explicitly choose it.
  See [Claude sign-in](../wiki/User-Guide/Sessions.md#claude-sign-in).
- Terminal reconnects can reclaim your own unsent input when nobody holds
  control. Other people still need confirmation, and a second live window stays
  read-only. The terminal explains when unsent input caused read-only mode.
- Session review authorization, Inbox permission reads, recovery enrollment and
  privileged update checkout checks are tightened. Claude credential filtering
  also covers MCP delivery.

## Fixes

- Existing repository folder provisioning and repair work more reliably under
  folder policy. Protected backup paths inside the human owner's home are
  accepted; agent-home targets and ambiguous protected paths are refused.
- Installer dry runs work on fresh and unprivileged hosts and validate host
  folder settings before deployment. Root-private settings still require sudo
  for a complete check; a dry run does not simulate a full installation.
- Terminal control labels fit better, session highlighting survives switching
  tabs, and host and Settings navigation mark the current item.
- Layout saving on upgraded databases is repaired, SQLite contention handling
  is improved, and transcript indexing retries after fresh activity.

## Upgrade notes

Once rc.4 is published, follow [rc.3 → rc.4](../wiki/User-Guide/Updating.md#rc3--rc4)
for backup, upgrade, verification and rollback. Keep a consistent database and
secrets backup plus separate workspace backups. PostgreSQL requires an independent
backup and recovery procedure; built-in rollback covers default SQLite only.

Three migrations run automatically:

- **0085** creates the missing layout file-reference table on affected upgraded
  installs, fixing layout saves. It does nothing if the table already exists.
- **0086** creates storage for salted recovery-code hashes. It does **not** generate
  codes for existing accounts. After upgrading, open **Settings → Account →
  Security → Sign-in recovery codes**, verify your sign-in and generate a set.
  Save them offline; each code works once and a new set invalidates the old set.
- **0087** stores the Claude sign-in choice. It backfills existing Claude sessions
  that received Anthropic auth credentials as API-key sessions, including recorded
  retired keys, and existing Claude schedules without an explicit choice whose
  projects have applicable credential grants as API-key launches. This preserves
  their previous credential delivery; other sessions default to subscription.
  Review scheduled launches after upgrading.

Folder/USB backup setup needs **one root command**: mount the disk, choose an
existing absolute folder in Host → Backups, select **Show console command** and
run the displayed command in the server's root console, for example:

```sh
sudo rynhult-admin backup add-folder -- /mnt/recovery
```

Then export a new recovery kit, make a backup and explicitly enable scheduling
when ready. Follow [Backups](../wiki/User-Guide/Backups.md#back-up-to-a-folder-or-usb-disk)
for ownership, path and disk requirements. This does not back up project workspaces.

## Batch 11

- Inbox hook actions target the intended pane. Toggle changes leave an audit record.
- Push explains refusals and offline machines. Add key shows the project name
  so you can check where the key will be used.

## New layout

The new layout is the only layout for everyone signed in. Classic is retired.
Existing saved classic choices no longer change the layout; their stored values
are retained for now. Settings no longer offers a layout choice, and Features
no longer offers a New layout switch. Choose features and Setup level instead.

Overview has a compact, dismissible prompt linking to **Settings → Setup level**.
