## Installation fix

Installers now explicitly use `umask 022` for application code instead of inheriting
an administrator's stricter `027` or `077`. This fixes installation failures such as
`Permission denied` when the `acc` account opens `/srv/acc/app/deploy/lib/vault-key`.
Linux main and node installs, macOS and WSL entry points, and the shared offline/
queued update entry point use the same default. Vault keys and private settings
retain restrictive modes; service settings are private from their first write.

On rc.1 or rc.2, run `umask 022` in the administrator shell before the documented
setup command. Keep following the Guide's [Updating](../wiki/User-Guide/Updating.md)
procedure for existing installations; rerunning a new setup over an older checkout
is not an upgrade procedure. Do not recursively open permissions on data or secrets.

The disposable-VM rehearsal keeps its evidence directory private. Its separate
`--strict-umask` mode installs the candidate fresh with an inherited `077` and
checks code readability, private keys/settings and service health. The ordinary
mode retains rc.1 installation, signed upgrade and rollback qualification.
